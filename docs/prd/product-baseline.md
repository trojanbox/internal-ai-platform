# 产品基线

本文件是产品规划的权威前提。内容来自 [#320](https://github.com/trojanbox/project-documents/issues/320) 的讨论结论，其中「已确认」条目来自用户的明确选择，其余为待审建议。任何后续规划不得与已确认条目冲突；确需变更时先取得用户确认，并在此处记录取代关系。

当前状态：`skeleton_confirmed`（2026-11-01）。整体功能范围与模块职责已由用户确认，可以开始逐模块细化；模块细化不得改变本文件的骨架边界。

## 1. 产品定位

面向企业内部的云端 AI Agent 平台，以类 ChatGPT 的聊天体验为主要入口，把企业内部各系统的业务能力与流程入口汇集到同一处。

产品不预置采购、人事、财务、审批等行业业务流程。业务操作、业务规则和流程编排由插件或外部系统提供（D-012）。平台自身只提供通用的对话、Agent 运行、插件管理、个人空间、任务运行和外部连接能力。

| 项目         | 内容                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------- |
| 目标用户     | 企业内部员工                                                                                      |
| 两类目标场景 | 已有系统的企业：通过插件接入现有软件；新企业：围绕平台与插件组织自己的工作方式                    |
| 形态         | 仅云端服务（D-018），用户以浏览器访问，不提供本地独立版本                                         |
| 组织边界     | 每企业一套云端空间（D-020）；共享插件与项目分享只在本企业内生效                                   |
| 非目标       | 面向公众的通用聊天产品；平台内置企业业务流程引擎；独立本地部署版及跨版本同步/迁移；跨企业插件市场 |

## 2. 事实基线

- 产品骨架已由用户确认（2026-11-01），当前处于模块细化阶段；仍没有产品源码、原型、运行日志或真实企业数据。
- Pi、MCP、OIDC、交互式 UI、多机协调等**均为待验证的探索方向**，不代表已选定技术方案。
- 本仓库当前是全栈脚手架（React + NestJS），除模板自带能力外没有任何产品功能实现。
- 可借鉴 ChatGPT、Claude、Copilot Studio 的产品能力，但不得把其能力表述为本产品已具备。

## 5. 六大产品区域

产品范围内只保留六个用户可见区域，不因功能增加而新增第七个区域或独立子系统。企业空间是作用域边界，不是第七个功能区域。

| 区域                   | 唯一主责                                                                                               | 可协作使用其它区域                                          | 不得在本区域重复承担                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1 聊天与交互           | 对话消息、输入与展示方式（含语音/图片入口）、插件页面的展示容器、内容预览与用户反馈                    | 展示 Agent 回复、内容空间文件、任务状态、插件返回结果       | Agent 推理、插件执行、文件长期保存、企业业务状态、任务排程               |
| 2 Agent 与模型         | 模型使用、规划推理、当前任务上下文、决定调用哪些可用工具、处理工具返回内容                             | 按需读取项目资料与记忆、调用插件、向任务管理报告进展        | 账户/项目/文件的长期归属、插件安装管理、企业流程定义、独立的任务排程系统 |
| 3 插件管理             | 插件目录与搜索、安装启停升级、已安装能力清单、插件配置与适用环境、本企业共享插件与个人插件的可用性入口 | 读取用户与空间权限、供 Agent 发现能力、供聊天承载插件 UI    | 业务系统主数据、企业审批规则、聊天历史、项目文件                         |
| 4 用户、组织与内容空间 | 用户与个人设置、企业内团队/工作区、项目/主题、资料与文件及成果的长期管理、长期记忆、模板、内容可见范围 | 向 Agent 提供经授权的资料引用、向聊天返回可展示内容         | 模型推理、任务调度、插件执行、外部系统原始业务数据                       |
| 5 任务与运行管理       | 通用 Agent 任务的状态、进度、停止与继续、结果索引、操作记录、通知、计划与周期任务、云端多节点协调      | 发起 Agent 任务、展示插件执行反馈、引用内容空间已保存成果   | Agent 推理与工具选择、采购/审批等业务流程、插件内部业务状态              |
| 6 外部系统与能力连接   | MCP 直接连接及第三方账号的添加与断开、授权状态、可用能力说明、来源展示                                 | 直接 MCP 工具与插件工具均供 Agent 使用，插件可复用 MCP 连接 | 插件安装与更新、专业系统或企业业务逻辑重建、默认授予全部 MCP 权限        |

核心原则：**每份内容、每个执行状态、每项业务规则只设一位主责**。其他区域可以调用、引用、展示，但不得维护冲突副本。

## 7. 使用路径

三条路径都只描述产品语义，不代表现成接口或已实现能力。

1. **聊天主动任务**：用户在项目内聊天 → Agent 在被允许的资料范围内理解任务 → 从直接 MCP 连接或插件目录取得当前用户可用工具 → 第三方连接核对授权 → MCP 服务或插件访问企业系统（插件可复用 MCP）→ 任务管理跟踪有运行过程的任务并记录操作 → 聊天展示结果，内容空间（个人或团队）保存选定成果。
2. **插件页面主动操作**：用户进入插件自定义页面 → 插件展示并发起业务动作，需要 Agent 时由 Agent 参与 → 授权与外部系统按原规则处理 → 通用任务状态与失败反馈 → 结果回到插件页面或会话；固定业务流程仍归插件。
3. **定时或长期任务**：用户创建周期任务 → 任务管理按计划发起 Agent 或插件执行 → 使用已授权的 MCP/插件工具读取资料或调用系统 → 任务管理记录状态、操作记录、通知或回访入口 → 用户查看结果；不因此引入平台内置业务流程。

普通即时问答直接作为会话消息呈现，不强制转为长任务。

**共通失败路径**（待细化）：未安装或已停用插件、第三方连接未授权、企业系统拒绝操作、任务失败或取消时，由对应责任方给出原因，通用任务与交互界面展示下一步；不得静默执行越权替代操作。
