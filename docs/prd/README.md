# 产品需求与规划文档

`docs/prd/` 存放本产品的长期规划基线：产品定位、已确认决定、模块职责边界、使用路径与待决问题。这里的内容用于后续需求拆解、MVP 排序和实现规划，不描述当前代码已经具备的能力。

## 文档定位

- 这里只记录**产品层事实与约束**，不记录接口设计、数据库结构、算法或部署方案。
- 用户明确确认的决定与助手建议必须分开标注；未确认内容一律标为待审，不得当成需求。
- 产品讨论的原始过程留在项目 Issue 中，这里只沉淀结论和稳定边界，不复制讨论全文。

## 维护规则

- 决定变更时更新对应文档，保留取代关系，不静默改写已确认结论。
- 新增文档前先检查是否与现有文档重复；能合并的不新建。
- 产品结论只能在用户明确确认后写入；助手建议保留「待审」标记。
- 技术实现细节待产品骨架确认、进入模块细化阶段后再补充。
